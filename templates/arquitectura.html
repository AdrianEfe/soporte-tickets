Arquitectura del sistema

Descripción

Sistema web para gestionar un servicio de soporte técnico informático. Registra los clientes, sus equipos, los técnicos y cada orden de reparación (ticket), con su problema, estado y costo.

Tecnologías

CapaTecnologíaFunción
PresentaciónHTML + CSS (plantillas Jinja2)Las páginas que ve el usuario en el navegador
LógicaPython + FlaskRecibe los pedidos, valida los datos y consulta la base
DatosSQLiteBase de datos relacional guardada en el archivo soporte.db
VersionesGit + GitHubHistorial de cambios y publicación del código

Cómo funciona

  1. El navegador pide una página, por ejemplo /tickets.
  2. Flask ejecuta la función asociada a esa ruta, que consulta la base con SQL.
  3. La base devuelve las filas pedidas.
  4. Flask completa una plantilla HTML con esos datos y la devuelve al navegador.

Es una arquitectura cliente-servidor de tres capas: presentación, lógica y datos.

Modelo de datos

  • Un cliente tiene muchos equipos; cada equipo pertenece a un solo cliente (1 a N).
  • Un equipo puede tener muchos tickets a lo largo del tiempo (1 a N).
  • Un técnico atiende muchos tickets; un ticket puede no tener técnico asignado todavía.

Las relaciones se implementan con claves foráneas: la base no permite que un registro apunte a otro que no existe.

Seguridad

  • Consultas parametrizadas: los datos que escribe el usuario se pasan con ?, separados del código SQL. Así se evita la inyección SQL.
  • Consulta libre en solo lectura: esa página abre la base en modo de solo lectura, por lo que no se puede modificar ni borrar nada desde ahí.
  • Validaciones: la base exige campos obligatorios (NOT NULL), emails sin repetir (UNIQUE), estados válidos y costos no negativos (CHECK).
